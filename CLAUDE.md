# Store clone — agent guide

Reverse-engineered rebuild of the Apple online store design (apple.com/store, `/shop/...`, `/retail`, `/today`)
from measurements of the rendered pages. Goal: a 1:1 layout match (sizes, spacing, animations, interactions) in
clean, open-source code. The repository holds the shell and fictional demo content only: no Apple text, image,
font or code is versioned.

Design: `DESIGN.md` is the source of truth; read it before touching any UI.

## Getting started

- No build step. Tools need Node, Playwright and pngjs: `npm install && npx playwright install chromium`.
- `npm run check` (= `node tools/check-pages.mjs`): JS errors, overflow at 1440 / 390 px, dead links, on every
  clone page and kit page. Run it before every commit; CI runs it on each push and PR.
- `.github/workflows/site.yml` deploys the demo mode to GitHub Pages on every push to `main`.
- `_analysis/` and `content/` are git-ignored: they quote or contain original content and never get published.
  Tools that write there (scoreboard, live cache) create them locally.
- `content/live/routes.json` lists the pages the scoreboard measures (62 at last count).

## Architecture

- Vanilla HTML + CSS + JS, no build. `index.html` = store home; `pages/*.html` = one file per template
  (29 pages, including `pages/components.html`, the component showcase).
- `assets/css/tokens.css` (copy of the Tokens block of `DESIGN.md`), `base.css`, `components/shell.css`
  (nav, menus, search, bag, mobile menu, ribbon, footer), `components/components.css` (buttons, shelves,
  cards, modal, accordion, tabs, options, swatches, gallery, summary, product bar, autoplay carousel).
  `assets/css/pages/*.css`: styles for one family of templates.
- `assets/js/shell.js` injects nav + ribbon + footer into `<div data-shell="nav|footer">`.
  `assets/js/components.js` wires behaviours through `data-*` attributes (list at the top of the file).
- Script order in a page: `content.js` → `live/shelves.js` → `live/dd-blocks.js` (configurators and simple
  buy pages) → `live/<template>.js` → `shell.js` → `components.js` → page JS.

## Demo mode and live mode

- **Demo mode** (default, the only mode published online): fictional "Pear Store" products (jPhone, jPad,
  PearBook, jMac, Pear Watch, PearPods, HomePear, Pear TV, PearTag, Pear Vision Pro); name map in
  `tools/rename-map.json`; pear logo in the nav and as favicon (`assets/img/pear.svg`); product images are
  "<Product> image (detail)" pills on a transparent background, generated by `node tools/demo-placeholders.mjs`.
  `content.js` forces demo mode outside localhost.
- **Live mode** (local only, never deploy it): the original content is fetched at runtime and rendered into the
  clone's templates.
  - `node tools/live-server.mjs` → http://localhost:4321/?content=live (`?content=demo` to switch back; the choice
    is kept in localStorage). `/__go?src=/shop/...` extracts the original page (≈ 11 s, then cached), detects its
    template (`tools/extractors/detect.mjs`) and redirects to the local page with `?src=`: every product gets its
    own page. `/__live?src=...[&fresh=1]` returns the JSON.
  - Extraction: `tools/extractors/<template>.mjs` (a self-contained function run inside the original page;
    optional `extractMobile()` replayed at 390 px → `data.mobile`). On every page also: card shelves
    (`extraShelves`), `dd-*` blocks (`ddBlocks`: compare, setup, services), legal notes (`legalHTML`), original
    nav and footer (`content/live/_nav.json`).
  - Rendering: `assets/js/content.js` (`window.Live`, places extraShelves / ddBlocks / legalHTML, removes the demo
    ribbon), then `assets/js/live/<template>.js` (`Live.register`).
  - 8 live templates: shelves, configurator-2 (every configurable purchase: Mac, Watch, iPad, Vision, iPhone;
    steps in the side rail, full-width steps and summary on iPhone), flagship (AirPods, HomePod, displays, TV),
    product (product pages, gift card), catalog (accessories, bands, grids), catalog-2 (refurbished, upgrade),
    content (trade-in, carriers, delivery), service (help, bag, sitemap, stores, Today, gift cards).
  - Cache and routes: `content/live/` (git-ignored, never published).
- Marketing pages (apple.com/homepod-mini, etc.) are out of scope; only their dot-and-progress-dash carousel
  was rebuilt (`[data-autoplay]`).

## Reusable kit (`kit/`)

- Separate from the clone: the clone keeps its measured values; the kit uses the same values as defaults with
  nothing hard-coded: `--kit-*` tokens (`kit/css/tokens.css`), component variables (`--card-w`…), fluid type with
  `clamp()` between 734 and 1068 px, container queries, `@layer kit.*` (user CSS wins).
- Files: `kit/css/kit.css` (entry point, `@import`), `kit/css/components/*.css` (each file starts with its
  markup), `kit/js/kit.js` (`data-kit-*`), `kit/index.html` (showcase), `kit/examples/*.html`, `kit/README.md`.
- Components: buttons/links (`kit-btn--outline`, `kit-btn-row`), headers, cards (`kit-card--icon`), product card,
  shelf, local bar, steps/options/swatches, gallery, summary, accordion, global nav (menus, search, bag, mobile),
  footer, modal (`<dialog>`), tabs, autoplay carousel, compare, "What's in the box", ribbon (`data-kit-ribbon`),
  category row (`catnav.css`), bag page (`data-kit-bag`, `KitBag`), store finder (`data-kit-stores`, `kit-field`).
- Clone pages do not use the kit: the live renderers write the clone's classes. Kit fidelity is measured by
  rebuilding a demo page with the kit and diffing it against the clone (`visual-diff.mjs`):
  `kit/examples/store.html` scores 99/100 at 1440 px and 97/100 at 390 px against `index.html` (command in
  `kit/README.md`).

## Tools (all in `tools/`, procedures in `docs/MAINTENANCE.md`)

| Command | Role |
|---|---|
| `node tools/live-server.mjs` | live + static server (one only, port 4321) |
| `node tools/refresh-live.mjs [filter]` | re-extracts cached pages (after an extractor or source-site change) |
| `node tools/scoreboard.mjs [filter] [--only-table]` | visual diff of every page → `_analysis/visual/SCORES.md` (≈ 1 min/page, ≈ 25 min for all) |
| `node tools/visual-diff.mjs <local> <source> <out>` | section-by-section diff of one page (+ worst-N.png) |
| `node tools/compare.mjs <local> <source> <out> [--width 390]` | computed-style diff + side-by-side tiles |
| `node tools/check-pages.mjs [--live]` | JS errors, overflow at 1440/390, dead links; run before every commit |

Server health: `curl -s localhost:4321/__ping` → `live`. Target fidelity: every page ≥ 97/100 (100 is out of
reach: fonts, changing content, videos).

## Code rules

- Values come from `tokens.css`; a measured value outside the tokens carries a source comment. A new hard-coded
  colour goes into the "Colours outside tokens" appendix of `DESIGN.md`, or becomes a token.
- Never copy heights or positions from the original into the data: layout comes from CSS. Accepted exception:
  CSS values the original page writes itself (e.g. `stepGap` as an inline style).
- Shared components first; a new need goes into `components.css`, not a page CSS.
- No `!important`, except the reduced-motion rule in `base.css` (standard accessibility pattern).
- No Apple text, image or code in the repo; original content only flows through the live JSON. Never commit a
  screenshot of live mode.
- Code comments in English.

## Pitfalls

- Live links: `Live.link` (content.js) sends marketing pages (`/mac`, `/iphone-17`…) to the matching store page
  (`STORE_PAGES`, `STORE_FAMILIES`); only pages with no equivalent (services, iCloud, AppleCare…) go to the origin.
  `/shop/buy-airpods` is a 404 on the origin: AirPods → `/shop/goto/airpods/accessories`.
  An `href="#"` link = an action that is not cloned (panel, save): components.js prevents the jump to the top.
- Server: a plain `kill` does not always stop it → `kill -9` the PID on port 4321, wait for the port to free up,
  restart. Never start a second server or standalone probe scripts alongside it.
- `networkidle` is never reached on apple.com: wait for `load`, then scroll with the wheel (`scrollThrough`),
  otherwise lazy shelves stay empty (`rf-cards-scroller-itemview`).
- Full-page screenshots render `loading="lazy"` images empty: live renderers use eager images.
- The original legal notes contain a hidden duplicate: drop `display:none` elements.
- The visual diff pairs sections by title: a missing title on our side merges two sections and drops their score
  (not always a rendering bug).
- Live mode uses locally installed SF Pro Text/Display (base.css); without it, line breaks differ from the origin.
- The origin computes some step margins at runtime and they vary between loads (Payment step): a score can move
  by ±2 with no code change.
- Known leftovers: 16 duplicate selectors in content/catalog-2/service CSS (split by an `@media`, merging risks
  cascade changes); `.localbar` has no z-index / title-size variant (local modifiers instead).
- zsh: `echo '...\n...'` turns `\n` into a newline; write probe scripts with a heredoc.
- macOS: `xargs -d` does not exist; zsh does not word-split `$VAR` (use arrays).
